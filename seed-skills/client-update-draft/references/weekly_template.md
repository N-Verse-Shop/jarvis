# Weekly Update — Template

A canonical structure. Always include all six sections; drop bullet
points only when the section has zero true items (then write "Nothing
to report this week" — never invent filler).

## Header

```
Hi <First Name>,

Week N · <project name> · <YYYY-MM-DD to YYYY-MM-DD>
```

## ✓ Done

- 3-5 concrete deliverables shipped to staging or prod.
- Each bullet ends with the artefact (link, PR, demo URL).
- No "started working on" — only "merged / deployed / signed off".

## → Up next

- 2-3 items in flight this coming week.
- Time-boxed: "by Wed" / "before review".
- Include any external dependency: "blocked on logo file from Markus".

## Questions for you

- 1-2 *concrete* questions whose answer changes our next step.
- Examples that drive velocity:
  - "Approve Stripe live keys today, or wait for board call Tuesday?"
  - "Should we ship without the Polish translation (saves 3 days)?"
- Never: "any feedback?" or "thoughts?"

## Numbers (optional)

- Hours burned vs estimate.
- Bundle size / API latency / Lighthouse — if delta.
- Skip section if no number moved.

## Risks (optional)

- One sentence per risk + current mitigation.
- Be honest. "Logo file still missing — using placeholder. Will rebrand
  in 30 min when received."

## Calendar

- Auto-include: "Review call Friday 14:00 CET. Reply if reschedule."
- If user already has it on calendar — confirm instead.

## Footer

```
Best,
Danylo Molyanko
Nexus Studio · Rehburg-Loccum
nexus-studio.de
```

DE / UA / EN — match client language exactly. Body in their language,
sign-off in English is always acceptable.
